### 2.2 Docker 설치 (Ubuntu 기준)

서버에 Docker가 설치되어 있지 않은 경우, 아래 명령어를 순서대로 실행합니다.

```bash
# 1. 기존 Docker 패키지 제거 (충돌 방지)
sudo apt-get remove docker docker-engine docker.io containerd runc

# 2. 필수 패키지 설치
sudo apt-get update
sudo apt-get install -y ca-certificates curl gnupg lsb-release

# 3. Docker 공식 GPG 키 추가
sudo mkdir -p /etc/apt/keyrings
curl -fsSL https://download.docker.com/linux/ubuntu/gpg | sudo gpg --dearmor -o /etc/apt/keyrings/docker.gpg

# 4. Docker 저장소 추가
echo \
  "deb [arch=$(dpkg --print-architecture) signed-by=/etc/apt/keyrings/docker.gpg] https://download.docker.com/linux/ubuntu \
  $(lsb_release -cs) stable" | sudo tee /etc/apt/sources.list.d/docker.list > /dev/null

# 5. Docker Engine 설치
sudo apt-get update
sudo apt-get install -y docker-ce docker-ce-cli containerd.io docker-buildx-plugin docker-compose-plugin

# 6. Docker 설치 확인
docker --version
docker compose version

# 7. 현재 사용자를 docker 그룹에 추가 (sudo 없이 사용 가능하게)
sudo usermod -aG docker $USER
newgrp docker
```

### 2.3 로컬 개발 환경 설치 (선택 - 로컬에서 직접 실행할 경우)

Docker 없이 로컬에서 직접 개발/실행하려면 아래 소프트웨어가 필요합니다.

**Backend:**
```bash
# JDK 21 설치 (Ubuntu)
sudo apt-get install -y openjdk-21-jdk

# 설치 확인
java -version
# 출력 예: openjdk version "21.x.x"
```

**Frontend:**
```bash
# Node.js 20 설치 (nvm 사용 권장)
curl -o- https://raw.githubusercontent.com/nvm-sh/nvm/v0.39.7/install.sh | bash
source ~/.bashrc
nvm install 20
nvm use 20

# pnpm 설치
npm install -g pnpm

# 설치 확인
node -v    # v20.x.x
pnpm -v    # 9.x.x
```

**AI Server:**
```bash
# Python 3.11 설치
sudo apt-get install -y python3.11 python3.11-venv python3.11-dev

# FFmpeg 설치 (필수 - 오디오 변환에 사용)
sudo apt-get install -y ffmpeg libsndfile1

# 설치 확인
python3.11 --version   # Python 3.11.x
ffmpeg -version        # ffmpeg version x.x.x
```

## 10. Nginx 및 SSL 설정

### 10.1 Nginx 설정 파일 설명

**파일 위치:** `meari-fe/nginx/nginx.conf`

```nginx
# ── HTTP → HTTPS 리다이렉트 ──
server {
    listen 80;
    server_name i14c207.p.ssafy.io;
    return 301 https://$host$request_uri;    # 모든 HTTP 요청을 HTTPS로 전환
}

# ── HTTPS 서버 ──
server {
    listen 443 ssl;
    server_name i14c207.p.ssafy.io;

    # SSL 인증서 경로 (Let's Encrypt)
    ssl_certificate /etc/letsencrypt/live/i14c207.p.ssafy.io/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/i14c207.p.ssafy.io/privkey.pem;
    ssl_protocols TLSv1.2 TLSv1.3;
    ssl_ciphers HIGH:!aNULL:!MD5;

    client_max_body_size 50M;                # 업로드 파일 최대 50MB

    # React SPA 라우팅 (HTML은 캐시하지 않음)
    location / {
        root /usr/share/nginx/html;
        index index.html;
        try_files $uri $uri/ /index.html;    # SPA 라우팅 지원
        add_header Cache-Control "no-cache, no-store, must-revalidate";
    }

    # 정적 파일 캐싱 (1년)
    location ~* \.(js|css|png|jpg|jpeg|gif|svg|ico|woff|woff2|ttf|eot)$ {
        root /usr/share/nginx/html;
        expires 1y;
        add_header Cache-Control "public, immutable";
    }

    # Backend API 프록시 (/api → Spring Boot)
    location /api {
        proxy_pass http://meari-spring:8080;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_connect_timeout 60s;
        proxy_send_timeout 60s;
        proxy_read_timeout 60s;
    }

    # WebSocket 프록시 (/ws → Spring Boot)
    location /ws {
        proxy_pass http://meari-spring:8080;
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection "upgrade";
        proxy_set_header Host $host;
    }

    # AI Server 프록시 (/ai → FastAPI)
    location /ai {
        proxy_pass http://meari-fastapi:8000;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
    }

    # OAuth2 프록시
    location /oauth2 {
        proxy_pass http://meari-spring:8080;
        proxy_set_header Host $host;
    }

    # 헬스체크
    location /health {
        access_log off;
        return 200 "healthy\n";
    }
}
```

## 12. AWS S3 설정

### 12.1 S3 버킷 생성

1. AWS Console 접속 → S3 서비스
2. "버킷 만들기" 클릭
3. 설정:
   - 버킷 이름: `{YOUR_S3_BUCKET_NAME}`
   - AWS 리전: `아시아 태평양(서울) ap-northeast-2`
   - 퍼블릭 액세스 차단: 모두 차단 (Pre-signed URL 사용)
4. "버킷 만들기" 완료

### 12.2 IAM 사용자 생성 및 권한

1. AWS Console → IAM → 사용자 → "사용자 추가"
2. 사용자명: `meari-s3-user`
3. 권한 정책 연결:
```json
{
    "Version": "2012-10-17",
    "Statement": [
        {
            "Effect": "Allow",
            "Action": [
                "s3:PutObject",
                "s3:GetObject",
                "s3:DeleteObject",
                "s3:ListBucket"
            ],
            "Resource": [
                "arn:aws:s3:::{YOUR_S3_BUCKET_NAME}",
                "arn:aws:s3:::{YOUR_S3_BUCKET_NAME}/*"
            ]
        }
    ]
}
```
4. 액세스 키 발급 → `.env`의 `AWS_ACCESS_KEY`, `AWS_SECRET_KEY`에 입력

### 12.3 S3 사용 용도

| 용도 | 설명 |
|------|------|
| 오디오 업로드 | 사용자 발음 녹음 파일 저장 |
| 오디오 다운로드 | AI 서버에서 분석을 위해 다운로드 |
| Pre-signed URL | 시청용(1시간), 업로드용(15분) 만료 |

#### 13.2.3 Jenkins Job 생성

1. Jenkins → "새로운 Item" → "Pipeline" 선택
2. Pipeline 설정:
   - **Definition:** Pipeline script from SCM
   - **SCM:** Git
   - **Repository URL:** GitLab 저장소 URL

3. **Build Triggers:**

                                                     env.GIT_BRANCH == 'origin/release'

                        message: message + " (<${env.BUILD_URL}|상세보기>)")

        }
    }

### 13.4 CI/CD 파이프라인 동작 흐름

#### 13.4.1 브랜치 전략

```
master (Main)
└── release (QA/Test) ────────────→ [빌드 + 배포]
    └── develop (Integration) ────→ [빌드만]
        ├── develop-fe (Frontend Integration)
        │   └── fe/feature/login
        └── develop-be (Backend Integration)
            └── be/feature/login
```

> **중요:** CI/CD는 `develop`과 `release` 브랜치에서만 동작합니다. `master`, `develop-fe`, `develop-be`, `feature/*` 브랜치는 Jenkins Pipeline이 실행되지 않습니다.

#### 13.4.2 파이프라인 단계

| 단계 | 트리거 조건 | 동작 |
|------|-------------|------|
| **Checkout** | develop, release 브랜치 | GitLab에서 소스 코드 체크아웃 |
| **Build** | develop, release 브랜치 | Backend, Frontend, AI 이미지 병렬 빌드 |
| **Deploy** | release 브랜치만 | .env 생성 → docker-compose 배포 |
| **Notify** | develop, release 브랜치 | Mattermost 채널에 성공/실패 알림 |

**브랜치별 동작:**
- `develop` 브랜치: 빌드만 수행 (배포 없음)
- `release` 브랜치: 빌드 + 배포 수행
- 그 외 브랜치 (`master`, `develop-fe`, `develop-be`, `feature/*` 등): CI/CD 동작 안 함

### 13.5 배포 시 주의사항

1. **CI/CD는 develop과 release 브랜치에서만 동작합니다.**
   - `release` 브랜치: 빌드 + 배포 수행
   - `develop` 브랜치: 빌드만 수행 (배포 없음)
   - 그 외 브랜치(`master`, `develop-fe`, `develop-be`, `feature/*` 등): CI/CD 동작 안 함
2. **Jenkins Credentials에 모든 시크릿이 등록되어 있어야 합니다.** (13.2.2 참조)
3. **배포 시 인프라(PostgreSQL, Redis, RabbitMQ)는 재시작하지 않습니다.** 애플리케이션 컨테이너(spring-api, frontend, fastapi)만 재배포됩니다.
4. **배포 후 미사용 Docker 이미지가 자동 정리됩니다.** (`docker image prune -f`)
